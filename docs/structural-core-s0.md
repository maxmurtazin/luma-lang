# Structural Core S0 — architecture audit

Baseline: remote main 4dec992146090811e40e40830851ae639a248390 (v0.1.3), fetched and verified 2026-11-10. Existing checkout clean; release chat reports publication complete. No active release changes were found. Scope: existing luma-lang only; no Studio, CAD operations, Living IR changes, keywords, icons or logo work.

## Actual architecture

- src/lib.rs owns lexer, recursive-descent/precedence parser, Node/Kind and half-open UTF-8 byte Span. AST contains procedural statements, namespaces (object), imports, functions, arrays, pipelines and match arms. It has no persistent identity, explicit inferred type, symbol table or execution plan. Group and pipeline syntax are preserved. Some pattern wrappers share spans with their children.
- src/semantic.rs is the whole-import-graph monomorphic constraint checker. Scope parents and Binding records implement lexical resolution, readiness, module privacy and function identity. Functions are predeclared; assignments constrain a binding's single type. Ty variables unify with occurs checking; unresolved obligations reject the program. Objects/modules are structural namespaces, not first-class records. User polymorphism, overloads and indirect calls are unsupported.
- Checker load canonicalizes paths, reads and parses each module once, rejects cycles, resolves use X to sibling X.luma. Report.programs retains the parsed snapshot consumed by runtime. Diagnostics and legacy graph file keys currently use basenames: this is safe for ordinary sibling imports but loses canonical provenance and can alias symlink-based multi-directory graphs.
- Checker id/edge builds graph schemaVersion 1 (producer luma-0.1C). IDs combine basename, byte range and role; builtins have special IDs. Graph contains definitions, expressions, references, modules, contains/reads/resolves_to/calls/callback/imports edges. Types are Rust Debug strings. Not every syntactic expression is visited through expr (notably callees and pipeline targets); positions are not stable under text edits. This graph is an Explorer interface, not a typed IR contract.
- Effects are a conservative owner set, propagated over calls/callbacks. Print, captures and unproven callback effects mark owners; parallel requires a named function without these flags. This is not an effect algebra or a proof of termination, runtime success, determinism or absence of local mutation. Capture readiness is checked at top-level calls. runtime_gates currently remains empty.
- src/runtime.rs executes the checked AST snapshot, with by-value arrays, namespace/function environments, bounded fuel/call depth/repeat and bounded native parallel workers. Index bounds, division by zero and runtime limits remain runtime checks. Runtime re-resolves names; S1 must not replace execution or claim validated structural edits.
- src/main.rs supplies syntax-only/check/graph/run/version. VS Code Graph Explorer consumes graph v1 and byte locations; existing VSIX/installer remains supported until Studio parity. No typed adapter API exists today.

## Decision: GO, additive read-only foundation

Reuse checker type substitutions, bindings, calls, captures and effect propagation. Record observations at existing semantic decision points; do not infer types/effects in a new AST walker. Add a syntax/source index only for stable IDs, parent/child relations and mapping observations to syntax. Expose structured types and resolution targets with explicit module/file identity, source snapshot identity and schema version. Keep legacy graph and all CLI paths operational. Invalid input must produce diagnostics and no usable typed program. Tests must cover mapping gaps (pipeline target, member/callee, match patterns), errors and deterministic serialization.

## Risks and migration

1. ID stability is scoped to a module-relative namespace and named declaration/body anchors. Whitespace/comments and unrelated named sibling declarations should preserve IDs; rename/move/reordering indistinguishable siblings may change them. Duplicate anchors need deterministic ordinals, not silent overwrites. Persisted edit identity needs a future S2 identity registry.
2. A source file identity is not its contents. Publish logical paths separately from exact captured content identity; do not reread disk after checking. Canonical paths are internal loading keys; relocation should not perturb valid exports.
3. Type/effect output must reflect bounded inference. Unobserved syntax is explicitly untyped, namespaces differ from values, and effect absence only means not flagged by this checker. No CAD effect capabilities are implied.
4. S1 is not SSA, a lowered execution IR or a lossless formatter. Keep parser/check/runtime contracts; future S2 introduces candidate snapshots and validation before commit, then S3 editing APIs, then Studio parity. Living IR remains independent; a future adapter consumes a valid schema-versioned typed snapshot and performs its own capability/unit/domain checks.
5. Audit baseline checks: existing conformance, runtime, graph, EN/RU docs/example scripts, extension tests and CI remain acceptance gates. S1 adds explicit structural tests and export evidence. No installer release/version bump required for this foundation.
