# CAD-2 · встроенный Living IR 2D

Встроенный адаптер хранит состояние `living-ir.2d.embedded/1` в
аутентифицированном реестре Core ProjectStore. Нативная ревизия Part и
ревизия встроенного 2D документа ведутся отдельно. Запись 2D
увеличивает ревизию проекта. Если пакет создаёт экструзию, в этой же
транзакции увеличивается нативная ревизия Part. Core фиксирует состояние и квитанцию одной
транзакцией SQLite. Адаптер использует временный решатель Living IR 2D в
памяти и передаёт кандидата в CAS Core.

Сборка включает запись по явному параметру `--ir2d`. Она использует
закреплённые версии поставщиков и оставляет исходные рабочие копии
провайдеров без изменений. Для включения 2D и доступа к B-rep из одной
базы соберите оба инструмента из изолированной сборки.

```sh
python -B tools/cad/prepare-brep-project.py "$CORE" "$BREP" "$BUILD" --ir2d "$IR2D"
cargo build --manifest-path "$BUILD/living-ir-core/Cargo.toml" \
  -p living-cad-viewer --features luma-cad,luma-embedded-2d --bin luma-cad-project
cargo build --manifest-path "$BUILD/native/Cargo.toml" --features luma-tasks
```

При отдельной сборке хоста можно применить
`tools/cad/prepare-core-project.py CLEAN_CORE --ir2d "$IR2D"` к отдельной
чистой копии Core. После регистрации 2D состояния используйте сборки с
`luma-embedded-2d` для чтения работающей базы. Сборка без расширения
отклоняет такой формат реестра.

## Команды владельца

Вызовы начинаются с `luma-cad-project DB PROJECT`. Передайте ключ владельца
как `LUMA_CAD_PROJECT_KEY`. Как и у остальных команд Core, `OPERATION`
задаётся 32 строчными hex-символами, а ожидания ревизий передаются
десятичными числами.

| Команда | Поведение |
| --- | --- |
| `2d-register PART PROJECT_REV OPERATION SEED.json` | Принимает валидный снимок Living IR 2D с `ownership_mode: embedded` и `document_id`, совпадающим с Part. |
| `2d-apply PART PROJECT_REV OPERATION BATCH.json` | Проверяет цель и ожидаемую ревизию 2D из нативного пакета команд, готовит кандидат и фиксирует его через Core. |
| `2d-luma PART PROJECT_REV REV_2D OPERATION BUNDLE.json` | Готовит типизированные команды эскиза, Draft и экструзии из Luma source bundle. |
| `2d-inspect PART` | Возвращает снимок и три ревизии. |
| `2d-solve-report PART SKETCH` | Возвращает отчёт принятого решения с DOF, рангом, остатками и ветвью. |
| `2d-propose-branch PART PROJECT_REV BATCH.json TOKEN.json` | Рассчитывает предлагаемую ветвь, показывает её решение и сохраняет аутентифицированный токен. |
| `2d-accept-branch TOKEN.json OPERATION` | Пересчитывает и сверяет предложение, затем фиксирует выбранную ветвь и квитанцию через Core CAS. |
| `2d-length-source PART PARAMETER` | Возвращает `source` с точной нативной ревизией и хешем Part, значение Length в метрах и ревизию проекта. |
| `2d-recipe-preview PART PROJECT_REV EMBEDDED_REV BUNDLE.json TOKEN.json` | Проверяет рецепт, рассчитывает 2D и нативный кандидат, сохраняет аутентифицированный токен. |
| `2d-recipe-apply TOKEN.json OPERATION` | Повторно рассчитывает кандидат и принимает результат через Core CAS. |
| `2d-recipe-info PART` | Возвращает сохранённый bundle, его хеш, ID профиля и экструзии и принятые ревизии. |

Хост 2D команд Luma поддерживает `sketch.create(sketch_id, plane_id,
profile_id)`, `sketch.point(sketch, id, x, y)`, `sketch.fix(sketch, id,
point, x, y)`, `sketch.line(sketch, id, from, to)`,
`sketch.circle(sketch, id, center, rim)`, `sketch.profile(sketch)` и
`draft.create(id)`. Для Draft доступны слой, точки, отрезок через
`draft.add(layer, id, from, to)` и перенос `draft.transform(entity, dx, dy)`.
Используются UUID, плоскость XY, координаты типа
Length и профиль `mechanical-si-v1`. Нативный решатель проверяет
замкнутость, пересечения, отверстия и ограничения до CAS.

`brep.extrude(feature_id, profile, height)` использует принятый в том же
пакете ProfileRef. Поддержаны один профиль XY с прямолинейной внешней
границей и круговыми отверстиями, положительная высота и пустой Part.
Нативный Sketch сохраняет ID исходных кривых и ревизию 2D снимка.
2D документ и авторская экструзия записываются одним Core CAS.
Экструзия закрепляет вычисленную геометрию Profile. Последующее
редактирование 2D сохраняет принятую ревизию экструзии доступной.
Для публикации тела после CAS используйте `luma-cad-brep source`,
`publish` и `measure`.

### Рецепт Sketch/B-rep

Первое принятие рецепта требует пустой нативный Part и зарегистрированное
состояние 2D без геометрии и внешних привязок параметров.
Рецепт определяет один эскиз XY, один профиль и одну положительную экструзию, которую объявляет
через `cad.output("solid", body)`. Каждая точка фиксируется один раз
в объявленных координатах. Для размеров можно использовать
`param.length` и передавать значение через `param.value`.
Для первого запуска используйте [рецепт пластины с отверстием](../../examples/cad/sketch-recipe.json).

```sh
"$PROJECT_CLI" "$DB" "$PROJECT" 2d-recipe-preview \
  "$PART" "$PROJECT_REV" "$EMBEDDED_REV" examples/cad/sketch-recipe.json recipe.token
"$PROJECT_CLI" "$DB" "$PROJECT" 2d-recipe-apply recipe.token "$OPERATION"
"$PROJECT_CLI" "$DB" "$PROJECT" 2d-recipe-info "$PART"
```

Для пересборки измените значения в исходнике и обновите digest bundle.
Например, ширину в поставляемом рецепте можно увеличить с 40 до 50 мм.

```sh
PYTHONPATH=tools/cad python3 -B - <<'PY'
import json
from pathlib import Path
from lcan import digest, encode

bundle = json.loads(Path("examples/cad/sketch-recipe.json").read_text(encoding="utf-8"))
entry, files = bundle["entry"], bundle["files"]
files[entry] = files[entry].replace('param.length("width", units.mm(40))',
                                  'param.length("width", units.mm(50))')
payload = {"bundle_version": {"$u64": "1"}, "entry": entry, "files": files}
bundle["source_digest"] = digest("luma.cad.source", encode(payload))
Path("wider-recipe.json").write_text(json.dumps(bundle), encoding="utf-8")
PY
```

Передайте новый bundle и текущие ревизии в `2d-recipe-preview`.
Сохраните UUID объектов, связи кривых и топологию плана.
Core пересчитывает решатель на принятом 2D состоянии
и одной транзакцией записывает исходник, 2D и нативную экструзию.
Повтор того же исходника сохраняет принятую ревизию, а предыдущие
публикации B-rep доступны по своим ID. Токен действителен пять минут
и закрепляет ревизию проекта и версию интеграции.

Принятый рецепт владеет геометрией Part. Сторонние правки через
2D-пакеты, нативный редактор и рецепт CAD-1 отклоняются. В этом
профиле размеры меняются через bundle. Командные overrides,
отсоединение рецепта и изменение топологии требуют дополнительных
маршрутов.

### Параметры Length из Core

`2d-length-source` читает нативный параметр по UUID из любого Part
того же проекта. В `parameter.set_literal` передайте полученный `source`
как `core_source`, а `value_m` как `value_si` с `quantity_kind: "length"`.
Core сверяет ревизию, хеш, тип и точное значение в том же реестре,
который используется для CAS. Предпросмотр ветви возвращает набор
использованных привязок в `core_read_set`.

При изменении нативной ревизии источника чтение принятой модели
показывает её сохранённое значение. Следующая запись требует явно
обновить или снять устаревшую привязку. Для обновления запросите новую
пару `source` и `value_m` и передайте её в одном пакете команд.
Новый запрос на принятие предложения со старой ревизией получает
`Conflict`.

Встроенный профиль поддерживает локальные зависимости 2D и эти привязки
Length. Универсальные внешние зависимости Living IR 2D, встроенные
проекции Core на листах и история undo/redo остаются за границами профиля.
Самостоятельный `lir2d` отклоняет сохранение embedded-снимка.

### Выбор ветви решателя

Для смены ветви пакет `2d-propose-branch` завершает команда
`sketch.propose_branch` с начальным приближением. Обычный
`2d-apply` отклоняет такую смену и направляет к предложению.
Предпросмотр показывает DOF, решение и токен ветви, сохраняя принятую
модель в прежней ревизии. Файл предложения создаётся без перезаписи.

Токен связан с проектом, Part, ревизиями проекта и 2D, сборкой
интеграции и хешем кандидата. Отчёт `expires_at` указывает срок
из жизни предложения провайдера в секундах Unix. При принятии Core
заново запускает решатель, сверяет хеш кандидата, проверяет срок и
атомарно записывает принятую ветвь. После фиксации повтор того же
запроса возвращает принятую квитанцию. Для нового запроса к
устаревшему предложению Core возвращает `Conflict`.

## Проверка

Для проверки сбоя транзакции добавьте `checkpoint-fault-injection`
в список features команды сборки Core. Запустите тест с обычным
самостоятельным `lir2d` из закреплённого checkout.

```sh
python -B tools/cad/test-embedded-2d.py "$PROJECT_CLI" "$IR2D" "$LIR2D" --brep-cli "$BREP_CLI"
cargo test --locked --manifest-path "$BUILD/native/Cargo.toml" --features luma-tasks
```

Сценарий 2D проверяет отказ до регистрации, запрет автономной записи,
отказ незамкнутого профиля, откат аварийной записи, повтор квитанции,
устаревшую ревизию, конфликт двух писателей, сохранение ID кривых
и инженерный объём опубликованной экструзии. Отдельный сценарий ветви
проверяет сохранение принятой геометрии при предпросмотре, подмену,
срок действия, несовпадение хеша кандидата, аварийный откат и повтор
квитанции. Проверка рецепта покрывает перестроение с сохранением ID,
откат при сбое, старый токен, неизменившийся исходник и измерение
текущей и исторической B-rep публикаций. Проверка привязок Core покрывает
подмену значения и хеша,
изменение исходного Part, отказ принять устаревшее предложение и
пересчёт после явного обновления привязки. Отдельная проверка B-rep
исполняет объявленные в Luma задачи над подлинной опубликованной
геометрией. [Задачи B-rep](brep-project.md)
