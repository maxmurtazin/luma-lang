# CAD-1 · очередь заданий

`luma-cad-jobs` проверяет задачи и сохраняет их в SQLite. Подготовка
`Plan::prepare` сверяет версию операции, отпечаток провайдера, схемы
выходов и именованных входов. Она отвергает циклы и включает транзитивные
зависимости только поставленных задач. Общий предшественник ставится один раз.

`admit` вызывается внутри той же SQLite-транзакции, где хост принимает
модель и исходник. Идентификаторы задач и соответствия intent → job
становятся доступны другим соединениям после COMMIT. Повтор плана возвращает
те же идентификаторы, а смена входов создаёт новую генерацию. Внутренний
savepoint откатывает частичную постановку DAG при ошибке.

Воркер получает только задачи своего провайдера с опубликованными входами.
`complete` сохраняет ссылку на проверенный манифест. Провайдер отвечает за
проверку байтов артефакта. `publish` фиксирует результат отдельно от завершения
вычисления. Историческая публикация сохраняет исходную ревизию. Для текущей
публикации одновременно сверяются ревизия и хеш источника, а также поколение
слота. Манифест результата с устаревшим источником остаётся в квитанции.
Повторное применение старых байтов с новым номером ревизии не оживляет старый
кандидат.

Отмена до публикации блокирует результат. После публикации она возвращает
`AlreadyPublished`. История попыток сохраняется, `retry` разрешает новый
захват после ошибки или отмены. После потери воркера его арендатор может
завершить зависшую попытку через `fail` с сохранённым номером. Старый
воркер после этого не сможет завершить новую попытку.

## Проверка без Core

```sh
cargo test --locked --manifest-path crates/luma-cad-jobs/Cargo.toml
```

Локальный набор проверяет откат модели и очереди при сбое до COMMIT,
восстановление идентификаторов после COMMIT, гонки двух воркеров и
отмены с публикацией, а также защиту от устаревших источников и слотов.
Стандартный CI Luma может выполнить тот же набор без приватного checkout.

Хост будущей интеграции устанавливает схему через `install` и использует
`TransactionBehavior::Immediate` для записей. Идентификаторы задач
действительны в пределах одной базы. Подключение очереди к Core ProjectStore,
языковые `jobs.*` и воркеры CAD-провайдеров входят в дальнейшую интеграцию.
[Профиль Core ProjectStore](core-project.md)
